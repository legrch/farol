# Installed consumed-empty maintenance

The one-shot `tooling/recover-installed-empty-chat.mjs` entry is owner maintenance,
not normal startup, reconnect, task resume, update replay, or a general reset.
It selects only the existing trusted owner's `Farol` profile and a
clean, packaged, exact source/build. The Go producer is independently reproduced.
There are no HOME, profile, executable, force, retry, or resume overrides.

The exact failed run/config/Quit and selected metadata digests must still match
under the Desktop and Computer maintenance leases. Both connector and backend
process scopes must be freshly absent. The failed Quit must belong after the
run's start and contain exactly `connector` and `go-core`, in either original
order. Its bytes remain failed and are preserved without being rewritten.

Go qualifies the complete consumed empty retirement chain, incarnation history,
Chat/results and Task namespaces, Computer access digest, and existing empty
mutation directory. It holds the existing mutation writer claim through the
synchronous maintenance visitor and final recheck. Any record, staging file,
unknown membership, reused generation, stale selection or changed namespace
refuses. A first lifetime without a consumed head is outside this operation.

The existing preservation protocol retains the complete physical Chat history
and original failure records in `chat-retired-<operation-id>`. A distinct new
maintenance owner retires empty state, publishes a new handoff, receives the
initiating host's separate exact ACK, exits normally, and records that exact
terminal. Only this new child is confirmed. The original failed lifetime's
retirement/ACK/terminal remain absent or unobserved; historical earlier ACKs are
retained. The original configuration and Computer grants remain unchanged.

The pending intent fences startup throughout preservation and host completion.
A failed or unknown effect remains fenced and must not be repeated. The final
intent move follows recorded terminal, completion readback, inactive connector
reconciliation, original run/Quit archival, namespace/process checks and lease
verification. The existing best-effort uncertainty-fence limits at a lost final
rename/durability result still apply; this command does not claim atomic snapshots
against writers ignoring locks or universal power-loss recovery.

Source tests use disposable native stores and mocked pipe events. The explicit
`TestNativeInstalledEmptyHostWithBuiltCore` lane verifies built bytes, original
ACK/terminal, preservation and subsequent Go cold start in a fresh synthetic
profile. None of these checks establishes saved-profile, UI, live-provider or
installed-product acceptance. Those require separate exact candidate evidence.
